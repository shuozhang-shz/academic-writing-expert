# Review and delivery

Use a full review for substantive manuscript work or an explicit audit. For local polishing, apply only relevant checks and keep the response proportional.

## Review in order of consequence

1. **Meaning and evidence:** Can the reader trace the major conclusions to supplied or checked support? Have observations, interpretations, and hypotheses stayed distinct? Are any apparent improvements actually changes in causality, generality, comparison, or certainty?
2. **Argument and structure:** Does the manuscript answer its question? Does each section and paragraph have a job? Are significant opposing or null findings retained? Does the discussion explain rather than merely repeat results?
3. **Quantitative and terminological consistency:** Do sample names, n, units, endpoints, baselines, uncertainties, acronyms, figure references, and definitions agree across the supplied components? Trace a changed central fact to every affected location.
4. **Language:** Inspect sentence attachment, precision, parallelism, voice, tense, grammar, punctuation, and needless repetition using the language reference. Respect the author's meaningful stylistic choices.
5. **Deliverable:** Check requested sections, word limit, formatting, citation markers, and output form. If only part of the paper was available, say the review covers that part.

For a full audit, separate a factual conflict or unsupported conclusion from an optional stylistic improvement. Describe each material issue using location, evidence, consequence, and a concrete repair or author question. Do not invent a numerical quality score or call a paper publishable because its language is fluent.

## Deliver the useful artifact first

| User intent | Default output |
|---|---|
| Simple polish | Revised passage, then brief notes only for material ambiguities or requested explanations |
| Substantive revision | Revised text plus a compact account of argument changes and unresolved scientific issues |
| Draft from notes | Supported draft with clearly isolated evidence gaps and necessary author decisions |
| Diagnostic review only | Prioritized findings and concrete revisions/examples; do not silently rewrite the entire file |
| Annotated edit | Readable before/after or tracked changes with meaningful comments |
| Strict clean text | Only the requested text unless a blocking ambiguity requires clarification or an explicit placeholder |

For an explanatory change table, useful columns are original, revised, reason, and meaning impact. Do not list every article or comma correction unless asked. If displaying reusable prose in a host that supports writing blocks, follow that host's format; a file artifact need not be duplicated in full in chat.

An unresolved issue is most useful when specific: 'Does the 8% increase refer to baseline-normalized signal or absolute efficiency?' is better than 'Please check the science'. Avoid repeated approval requests for already authorized editing. Offer alternatives for genuine interpretive choices, not arbitrary synonyms.

## Documents and source preservation

Keep the original when producing a separate revised manuscript unless the user asks for an in-place edit. Use a predictable revised filename or the existing project convention. Preserve citation fields, equation objects, table structure, figure identifiers, comments, and existing tracked changes unless the requested task changes them.

Use available document-format tools/skills when the user asks for DOCX tracked changes, PDF output, or edits to a connected document. Inspect the produced artifact and verify that text, references, equations, and layout survive. Markdown bold/strikeout is not Word tracked changes. When genuine redlining is unavailable, state the limit and provide an editable revision with a change table instead of claiming tracked changes exist.

Do not require document conversion for a short text-only request. No external publication, submission, or message to coauthors is implied by manuscript-editing authorization.

## Human review and AI disclosure

For substantial AI-assisted drafting, give the author a manageable list of scientific decisions that remain theirs to assess, especially alternative explanations, novelty boundaries, and missing sources. Do not claim that an internal model review equals independent expert validation or that the author has approved the draft.

If disclosure language is requested or submission preparation needs it, use the real tools and assistance performed, and the current target journal's verified requirements. Distinguish what the agent knows from what only authors can attest to. A draft statement may leave author confirmation fields, but do not state that all authors performed line-by-line review or accept responsibility unless they have said so. The examples in the thinking essays are source-specific accounts, not text to reuse as the user's own history.

## Completion and stopping

A task is complete when the requested writing artifact is delivered, relevant semantic and format checks pass, and consequential unresolved issues are accurately reported. A provisional draft can be complete as a provisional draft; it must not be labeled submission-ready while central evidence is absent.

For a short edit, no formal report or dossier is needed. For a whole manuscript, keep an accurate checked-scope record and unresolved-question list. Revise again only for an identified defect, a new source, or user feedback; repeated cosmetic passes can erase voice and introduce errors.
